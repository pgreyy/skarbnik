Rebuild it yourself

Level B of the judge guide. It builds the checker in a pinned container and compares the id.

./scripts/check_image_id.sh

The last line should read MATCH. It took 2 min 20 s with the Docker images cached, and 5 min 12 s with the 7.46 GB image download. Needs Docker.

Shown on one machine so far (docs/evidence/judge/check_image_id_home.txt).

What a match establishes

It does. The id on chain is the id of the public checker source, built the reproducible way.

It does not. It does not show that the checker is complete, or that a passing fix is secure against everything. A proof says one patch passed or failed this defined check.

What the checker runs on every patch

1
Validate the module

No imports, at most 2 memory pages, checked exports. The checker allows up to 2,048 bytes; each bounty sets its own limit (the open bounties use 1,024), shown in feed.json and on the bounty page.

2
Run the secret input

It must not crash or run out of fuel, 50,000 units per input, in a fresh interpreter each time.

3
Run the public tests

Every answer must match the original program’s.

4
Run fairness inputs

Drawn from the reveal seed, so a patch cannot be tailored to them. They must match the original.

5
Run crash variants

One or two byte changes of the secret must not crash where the original crashes.

Where every fee goes

An attempt fee is taken from your credit in the contract when your commit is counted. It never goes to the vendor.

Where every fee goes
How the attempt endsWhere its fee goesWhen
Never revealed in timeProtocol fee poolWhen anyone calls release_unrevealed after the reveal window, or at expire
Wins with a PASS proofBack to the winner, with the bountySame transaction
Paid by the timeout ruleBack to each account that shares the payout, with its shareSame transaction
Revealed and still waiting when another attempt winsBack to the committer as creditSame transaction
Decided FAILLevel 2 bounties: the protocol fee pool. Level 0: equal shares to the registered verifiersWhen anyone calls expire after the bounty’s expiry

The protocol fee pool cannot be withdrawn: no method takes NEAR out of it. Unspent credit is always yours: withdraw_credit returns it (it needs 1 yoctoNEAR, so only your full key can call it, never an agent’s limited key). docs/SECURITY.md, “Where every fee goes”.

Security Lab: how much can probing learn?

One verdict leaks at most one bit about the secret, so the attempt limit K is the leak budget. A probe agent tried to learn a 4,096 value secret one bit at a time. Step through what was recorded.

Limits

Known limitations, in plain words

These are the points a skeptical reader should check first. None of them is hidden elsewhere.

Testnet only

No mainnet contract exists. Every transaction on this site is a testnet transaction.

No external audit

The contract was reviewed in AI review passes, with every finding reproduced before it was fixed. The checker, scripts, site and agent were outside that review.

Full access key kept on purpose (testnet)

The testnet contract’s account keeps a full access key, so its owner can replace the code under live bounties. This is deliberate: it’s an experimental testnet contract that will keep changing. The mainnet contract (skarbnik.near) is planned without an upgrade key the owner controls alone (key removed, or upgrades behind a multisig or DAO with a delay). The keys could not be read just now. To check that the code has not changed silently, compare the live code hash on the Contract tab with the last deploy in docs/EVIDENCE.md, “Contract code and every deploy”, which lists every deploy transaction.

Vendor proofs are slow on a laptop

One attempt takes about 1.5 to 2.5 hours to prove on a laptop CPU, plus the shrink step, so it can miss a 4 hour window. Then the timeout rule applies.

GPU proving rents a machine

The vendor’s watch proves each attempt on a rented GPU (bounties 32 and 27): about 17 minutes from reveal to submit, about $0.04 of GPU a proof. The secret sits in that machine’s RAM during the proof, then is wiped. The Groth16 wrap needs Docker on an x86 machine.

A timeout pays whatever was revealed

The contract does not read the fix. Under a silent vendor, an honest fix may get as little as 1/K of the bounty.

Revealed fixes are public

After the reveal a patch is on chain. A one line fix is often the reference fix byte for byte, so a secret reference fix protects little.

Narrow scope

Crash bugs in small WebAssembly modules. Patch size: the checker allows up to 2,048 bytes; each bounty sets its own limit (the open bounties use 1,024), shown in feed.json and on the bounty page. A vendor with a crash but no fix is not supported.

A payout to a missing account is lost

Bounty 8 shows it. The site and the agent check the account before a commit, but the contract does not.

One verdict leaks one bit

K is the leak budget. A per-account cap (deployed 2026-10-26) limits how many slots one account holds, but one person with many accounts can still fill a bounty’s slots.

Level 1 is not built

The OutLayer path exists but never answered on testnet. Every current bounty is Level 2 or the older Level 0.

Wallets are mostly untested

NEAR CLI was clicked through to real transactions. The other wallets were only loaded, not signed in.

Status vocabulary

The same labels everywhere

Mint is used only for a verified outcome, and always with a word and an icon. A timeout is never styled like a proof. The last two labels are the feed’s states for bounties that are not settled.

Proof verified

The contract checked a proof for the paid attempt.

Proof rejected

A valid proof said FAIL for an attempt. The bounty is still open.

Awaiting evaluation

A patch was revealed and no verdict has arrived yet.

Timeout settlement

No proof arrived in the window. The contract paid by rule. This is not a proof.

Refunded

Nothing was paid out. The vendor got the reward back.

Failed

Past its expiry and not settled. Anyone can call expire to refund the vendor.

Demo or test only

A demo or test bounty, not settled yet. It uses a public input or a test setup.

Open for attempts

Opened by its Proof 0 and accepting commits now.

Waiting for Proof 0

Created, not opened yet. It opens when its Proof 0 is accepted.
