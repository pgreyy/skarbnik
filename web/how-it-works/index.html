The same story in plain text

Four steps, written out

1. A bug exists. The exploit cannot be shared.

The vendor has a private input that crashes its program. The input is needed to check a fix, but handing it to every outside agent would hand it to attackers too. So it stays on the vendor’s machine and only a fingerprint goes on chain. The vendor first proves its own reference fix passes, called Proof 0. The bounty opens only after that.

2. An agent fixes it without seeing it.

The agent reads the public task and code, writes a patch, and tests it against the public tests only. It then commits a fingerprint of the patch and, after a short gap, reveals the patch itself. It acts through a key limited to commit and reveal, and pays a rising attempt fee from credit prepaid into the contract.

3. The patch is checked, and only the result comes out.

The vendor’s evaluator runs the revealed patch against the secret input inside a zero knowledge machine. What leaves the machine is a proof and a short public record: hashes and a verdict, PASS or FAIL. The secret input is not in that record. The proof is a separate object from the secret, and it covers one patch against one defined check.

4. The contract applies the rule.

The contract checks the proof itself, at about 35 Tgas, and confirms every field in the record belongs to this bounty and this attempt. PASS pays the bounty and returns the winner’s own fee. FAIL spends the attempt. The contract does not run the private evaluation. It trusts only a proof from the one approved checker.

4b. If the vendor goes silent

If the vendor stays silent past the verdict window (set per bounty when it is funded), anyone can call claim_timeout. The bounty is split equally among revealed attempts that are still undecided. A late proof is refused. The contract does not look at the fix, so this path pays whatever was revealed. This is not a proof: a timeout payment shows only that the vendor did not answer in time.

Scope

What Skarbnik is, and isn’t

It is

  • A private repair bounty system on NEAR testnet
  • For small WebAssembly programs with a known crash and a reference fix
  • A way to check a fix against a hidden test, with a proof of that one check
  • A NEAR contract that holds the reward and pays by fixed rules
  • Open to AI agents and to independent developers

It isn’t

  • A security audit, or proof that a program is safe against everything
  • A tool for any kind of software, firmware or vulnerability
  • Production ready, or live on mainnet
  • A place where the secret goes on chain. Only its fingerprint does
  • A proof when a bounty is paid by timeout. A timeout is never a PASS
Skarbnik

Skarbnik is Polish and Ukrainian for treasurer, and in folklore the mine spirit who rewards honest miners.

On private bounties, researchers and the public never see the secret input. Demo bounties use a public input so anyone can check them.
